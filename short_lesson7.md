# Описание задачи

Нужно реализовать объектно-ориентированную систему отправки email-сообщений.

### Модель Письма (Email - dataclass)
- Письмо содержит поля: тема (subject), текст (body), отправитель (sender), получатели (recipients), дата отправки (date), сокращённый текст (short_body), и статус (status).
- Status (StrEnum): draft, ready, sent, failed, invalid.
- Recipients: Принимает один адрес или список адресов; всегда хранится как список.

### Модель Адреса (EmailAddress)
- Класс инкапсулирует email-адрес с методами:
- Нормализация: приведение к нижнему регистру и обрезка пробелов.
- Валидация: адрес должен содержать @ и заканчиваться на .com/.ru/.net. Невалидный адрес вызывает ValueError.
- Маскированный вывод: свойство masked (первые_2_символа + "***@" + домен).
- Подготовка Письма (Email.prepare()) - перед отправкой письмо должно быть подготовлено:
  - Очистка: subject и body очищаются от лишних пробелов и переносов. 
  - Валидность: Если тема, тело, получатель и отправитель непустые → статус READY, иначе INVALID. 
  - Short Body: Метод add_short_body() формирует сокращённую версию тела.
- Вывод: Метод __str__ должен использовать маскированный адрес отправителя и список получателей через запятую.

### Сервис отправки (EmailService)
- Метод send_email() имитирует отправку и возвращает список новых писем (одно на получателя).
  - Для каждого получателя создаётся глубокая копия исходного письма. 
  - Выставляется текущая дата отправки. 
  - Статус меняется на SENT, если исходный статус был READY, иначе FAILED. 
  - Исходное письмо и его поля не должны изменяться.

### Дополнительное задание
Создать класс LoggingEmailService, который наследуется от EmailService и переопределяет send_email для записи информации об отправке в файл send.log.

Код должен корректно:
- обрабатывать нормальные и граничные случаи
- поддерживать одного и несколько получателей
- не менять исходные объекты
- возвращать список отправленных писем со статусом и датой
